## 1. 项目概述

### 1.1 项目简介

Jit-Hub 是一个基于微信小程序的在线课程学习平台，提供课程浏览、搜索、购买、学习等完整功能，采用前后端分离架构。

### 1.2 项目目标

- 提供稳定、高效的在线课程购买服务
- 保证核心交易流程的正确性
- 确保用户数据安全
- 提供良好的用户体验

### 1.3 技术栈

| 分类 | 技术 |
|------|------|
| 前端 | UniApp + Vue 3 + SCSS |
| 后端 | Spring Boot 3.4.4 + MyBatis Plus 3.5 |
| 数据库 | MySQL 8.0 |
| 开发语言 | Java 17 |
| 目标平台 | 微信小程序 |

## 2. 测试范围

### 2.1 测试对象

1. **后端 API 接口**（11 个核心接口）
2. **前端小程序页面**（5 个主要页面）
3. **核心业务流程**（注册、登录、下单、支付）
4. **数据持久化**（数据库表操作正确性）

### 2.2 功能测试范围

| 模块 | 功能项 |
|------|--------|
| 用户模块 | 用户注册、用户登录、获取用户信息 |
| 商品模块 | 新增商品、精选商品、分类查询、商品详情、关键词搜索 |
| 订单模块 | 创建订单、支付订单、按状态查询、全量查询 |

### 2.3 非功能测试范围

| 测试类型 | 范围 |
|----------|------|
| 性能测试 | 页面加载时间、接口响应时间 |
| 兼容性测试 | 不同手机型号、不同微信版本 |
| 安全性测试 | 密码传输、越权访问、SQL 注入 |
| 用户体验 | 界面美观度、交互流畅度 |

### 2.4 不测试范围

- AI 解答模块（仅页面框架，后端接口未实现）
- 在线考试模块（仅页面框架，后端接口未实现）
- 聊天室功能（预留功能，未实现完整逻辑）

## 3. 测试策略

### 3.1 测试方法

- **黑盒测试**：基于需求文档和接口文档，不关注内部实现
- **手工测试**：不引入自动化测试工具，全部手工执行
- **端到端测试（E2E）**：模拟真实用户操作，验证完整业务流程

### 3.2 测试级别

| 级别 | 描述 | 执行者 |
|------|------|--------|
| 单元测试 | 后端 Service 层核心方法逻辑验证 | 后端开发 |
| 接口测试 | API 接口功能、参数、响应验证 | 测试人员 |
| 集成测试 | 前后端联调，验证数据流转 | 测试人员 |
| 系统测试 | 验证整个系统功能完整性 | 测试人员 |
| 验收测试 | 最终用户角度验证产品是否满足需求 | 测试人员 + 需求方 |

### 3.3 测试环境

| 环境 | 配置 |
|------|------|
| 操作系统 | Windows 10 / 11 |
| 浏览器 | Chrome 120+ |
| 小程序 IDE | 微信开发者工具 Stable |
| 后端服务器 | localhost:8088（开发环境） |
| 数据库 | MySQL 8.0，本地实例 |
| 测试数据 | 独立测试库，独立测试账号 |

### 3.4 测试工具

| 工具 | 用途 |
|------|------|
| Postman / Apifox | 接口测试 |
| 微信开发者工具 | 小程序前端调试 |
| Chrome DevTools | 网络请求分析 |
| MySQL Workbench / Navicat | 数据库验证 |
| Excel / Markdown | 测试用例与缺陷记录 |

## 4. 测试通过标准

### 4.1 接口测试通过标准

- 所有核心接口响应状态码：**200**
- 接口响应时间：**< 3 秒**
- 响应数据结构符合接口文档定义
- 业务逻辑正确性验证通过
- 异常场景有明确提示，不崩溃

### 4.2 功能测试通过标准

- 核心业务流程 100% 可走通：注册 → 登录 → 浏览 → 搜索 → 下单 → 支付
- 所有测试用例执行完成，**P0 / P1 级别用例 100% 通过**
- P2 级别用例通过率 ≥ 90%
- 无严重级别（S0 / S1）遗留缺陷

### 4.3 兼容性测试通过标准

- iOS 最新版微信：核心功能正常
- Android 最新版微信：核心功能正常
- 不同分辨率手机：页面布局无明显错乱

## 6. 风险与应对

### 6.1 项目风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| 开发进度延期 | 测试时间压缩 | 中 | 预留 2 天缓冲时间 |
| 需求变更 | 测试用例需重写 | 中 | 变更评估后再测试 |
| 环境不稳定 | 测试中断 | 低 | 本地开发环境独立运行 |
| 人员不足 | 测试覆盖不全 | 中 | 优先保证核心路径 |

### 6.2 技术风险

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 接口文档与实现不一致 | 联调失败 | 以实际接口返回为准，实时更新文档 |
| 数据库数据脏读 | 测试结果不可靠 | 使用独立测试库，每次测试前重置 |
| 前后端跨域问题 | 前端无法请求后端 | 本地配置代理，或后端开启 CORS |
